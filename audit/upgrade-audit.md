# Godot Prototype Studio 0.4.0 - upgrade audit

## Scope and conclusion

This release uses the supplied 0.2.0 autonomous router as its base, adds selected 0.3.0 QA/engine ideas, and raises complete-new-game craft to a bounded NEAR_RELEASE_SLICE. It is a complete skill bundle, not a patch. It was not installed into an account.

The artifact has been reviewed as instructions and executable Python utilities. No available Godot/Codex executable or successful engine-download path was established in this environment. Actual game generation, rendered Godot play, sound listening, target-platform exports, and human enjoyment are therefore NOT validated by this upgrade. The bundled starter remains a technical fixture.

## Research audit

Three search waves covered engine practice, art, UX/gameplay, AI generation and their limitations. The ledger contains 28 opened primary-source pages, with dates, applied claim, landing file and caveat. Search/selection was not a formal systematic review. Read-source dates are not release dates. Older mission-brief/Ponytail sources remain labeled historical, not freshly verified. No tutorial game art, shader preview or third-party engine binaries were bundled.

The strongest contrary evidence is retained: current game-generation benchmarks distinguish recognizable/runnable mechanics from complete game artifacts; model judges do not prove subjective fun; state injection is not normal reachability; vendor art consistency guidance does not prove good composition; AAA interviews do not validate an intervention for indie teams. No numerical gain or success probability is claimed for this skill.

## Review round 1 - goals, authority and architecture

Found and addressed:

- The attachment's default approval chain and fixed repair cutoff conflicted with delegated completion. Kept 0.2 authority rules; distilled optional tools rather than importing its router.
- The old visual canon defaulted to graybox. It now carries the near-release target but starts PROPOSED, not falsely user-approved.
- Quality risked becoming unlimited breadth. The new profile defines release-like craft in one complete small session, not accounts, economies, full content or store certification.
- Art consistency alone omitted composition, motion, UI and sound. Added an actual integrated runtime exemplar and critical-state review before content multiplication.
- Script/scene inspection could imply runtime knowledge. Static inventory retains instanced nodes and correct external script refs without resolving live inheritance.

## Review round 2 - executable checks and adversarial cases

Found and addressed:

- Imported comparison accepted weak evidence, boolean/nonfinite measurements and forced human authority. It now checks actual files/hashes and shared conditions, refuses invalid numbers, and permits brief-authorized selection.
- A beautiful screenshot could stand in for gameplay. The final quality record requires distinct evidence categories and a declared normal-start trace with observed completion/reset; injected-state checks remain local.
- Missing or forged media labels could pass record checks. Added nonempty file/hash and basic media-signature validation. This is not full decoding or proof of honest capture.
- Fixed defects need old failure evidence as well as final retest. Added separate observed-build identity without requiring old logs to masquerade as current ones.
- A near-release profile could be omitted to obtain legacy validation. Added required-profile argument taken from the brief.
- Asset review could overwrite an input/contact sheet or follow a dangling output symlink. Refuse these writes; bound per-batch image inspection.
- Default static inspection could overwrite stored runtime observations. Write a separate engine_static_context.json.
- First test run found a stale README audit link. Replaced versioned metadata and generated this actual audit record.

## Review round 3 - cross-file and behavioral consistency

Reviewed all active reference/template roles against the root. Final acceptance has one source: the brief. The final quality review links its criteria rather than introducing a competing design contract. Long provenance is maintenance-only; optional tools and compatibility templates are not a checklist to preload. Existing code/version/language and explicit rough-probe scope remain protected.

The generated four-image contact sheet was also inspected visually for readable labels and layout. Its intentionally varying fixture artwork demonstrates the limit: valid dimensions/alpha/pivots are not a style-quality verdict.

The 40 scenarios in tests/scenarios.md were examined as static instruction walkthroughs. They cover unauthorized stops/actions, rough-probe overreach, coherent-but-unreadable art, state injection, bot/human confusion, opportunity-aware metrics, target input, cold/warm behavior, mixed-build evidence, and finite completion. These were not 40 live agent/game runs and do not produce a success rate.

## Executed verification and limits

The pre-change baseline ran 53 utility tests. The final working-folder suite ran 129 tests successfully, including real CLI invocations on labeled fixtures; none are a Godot gameplay claim. The expanded suite exercises positive and negative quality records, image properties/contact sheets, comparison logic, scene parsing, release binding, and existing regression cases. Actual final counts/results and package SHA-256 are in the companion delivery verification JSON, generated after packaging. Test fixtures explicitly identify themselves as non-game evidence.

A fresh extracted archive is rechecked rather than assuming the working folder is the delivered package. The final hash and tests bind to the final ZIP and extracted content. Any subsequent edit requires new packaging/verification.

No known unresolved major instruction or utility defect remained after these bounded reviews. This is not a guarantee of perfection. The remaining material validation gap is live end-to-end use on representative Godot projects with actual visual/audio/input inspection and separately identified human experience evidence.

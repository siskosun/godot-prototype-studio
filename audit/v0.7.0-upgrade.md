# 0.7.0 upgrade audit

## Goal

Add three narrow capabilities without turning the skill into a heavier universal framework:

1. choose Godot only when it is the cheapest adequate route; offer simple H5/browser-native implementation when it is materially faster with no acceptance loss;
2. search for reusable prototype code before formal development, with special attention to current GPT-6/Astra examples, and copy/adapt compatible same-stack source instead of rebuilding;
3. close the evidence gap for rooms, LAN and two-device play by verifying the joint client/server session rather than promoting intermediate checks into multiplayer completion.

## Decisions

- Keep the mission brief as the single acceptance contract. Add an optional `Pre-development Route` section that new prototypes must resolve; legacy briefs remain valid.
- Do not silently switch technology. H5 is offered only when the stack is open and the same acceptance can be met materially faster/simpler.
- Treat `MartinDelophy/awesome-gpt-6-astra` as a discovery index only. Follow entries to original source, verify revision and license, and do not treat Astra attribution as a quality signal.
- Reuse code only when source is available and license is compatible. Pin the upstream revision, preserve attribution/license and baseline the untouched copy before adaptation.
- If an extremely similar reusable project uses another stack, ask once whether to change stack. Declining does not reopen the decision.
- Add optional reuse-scan and multiplayer-session templates rather than making every workspace heavier.
- Add runtime-instance identity to the bundled LAN server. A random instance ID is exposed in `X-GPS-Instance-ID`; preflight can bind the observed endpoint to the start record and current server source hashes.
- Do not claim that the bundled static server verifies a project-specific authoritative game server. Multi-client verification still requires the project's actual session/server path.
- Post-export player files are finalized before BUILD_ID stamping. Any later mutation invalidates the Web identity.
- Certificate trust stays a user/browser action. The skill must not bypass a hard browser certificate error or silently install trust.

## Expected gain

The primary gain is avoiding two expensive error classes: selecting a heavier implementation than the prototype needs, and declaring a multiplayer/Web artifact complete based on evidence from the wrong layer. Code reuse should reduce duplicated implementation when a close legal baseline already exists.

## Risk controls

- The route gate is conditional and asks only when H5 materially improves cost/time.
- The reuse scan is bounded by decision value, not exhaustive repository research.
- Unknown licenses force reference-only use.
- Cross-stack reuse always returns stack authority to the user.
- Multiplayer evidence is layered; lower layers never imply higher ones.
- Runtime hashes/headers prove identity continuity, not gameplay correctness or process health by themselves.

## External source note

The community-maintained `MartinDelophy/awesome-gpt-6-astra` README checked on 2026-09-14 described itself as a discovery list of GPT-6 Astra games and explicitly stated that inclusion is not an official recommendation/performance benchmark. Its entries vary: some expose source and browser-native stacks, while at least one verified catalog note records an author-stated GPT-6 Astra + Godot project without claiming an independent model audit. This supports using the list as a search seed, not as reuse authority.

# 0.6.0 negative-transfer scenarios

The following are behavioral acceptance cases for future live use, NOT executed-agent success claims. Utility tests exercise code/records; they cannot certify these behaviors.

| Condition | Expected behavior | Regression |
|---|---|---|
| One-line bugfix, no reusable finding | Reuse brief/progress; fix and test affected path | Mandatory memory database, four agents or art research |
| No separate reviewer available | Fresh-start labeled self-review; respect contracted independent-review requirement | Fake independent review or unconditional stop |
| Reviewer changes acceptance or a game file | Detect drift, preserve failure, establish new review identity | Reuse old PASS record |
| Hypothesis has matching file hashes | Keep it a hypothesis; check contextual scope | Promote it to fact or user approval |
| Rejected rule changed since last session | Reconsider only affected evidence and conditions | Treat historic failure as a permanent veto |
| A failed probe was caused by overwritten fixture | Fix harness and repeat before judging mechanic | Reject design from broken evidence |
| Matching contract but no runtime capability | State unverified required runtime evidence | Treat checkpoint MATCH as a playtest |
| Pixel-accurate dark/angular reference | Preserve explicit target; diagnose actual legibility conflict | Convert everything to warm/rounded art |
| Two strategic goals must coexist | Improve relative priority, preserve choice | Enforce exactly one goal |
| Player needs persistent help | Keep recoverable/accessibility cues | Remove help after the third attempt |
| Short competitive or finite narrative game | Preserve complete session without invented meta economy | Add XP, daily quests or failure materials |
| Visual perception is the mechanic | Keep causal sensory input in comparison | Remove the input and call the game a reskin |
| Idle/rhythm toy repeats one action by design | Judge against its actual promise | Demand strategic complexity for its own sake |
| Agent calls Input.action_press | Report polling-state test, not Node._input or OS/browser input | Claim actual focus, event propagation or touch support |
| First exemplar passes but critical variant fails | Repair variant/shared assumptions, keep batch evidence scoped | Certify every generated item from one sample |

# Behavioral regression scenarios

These are maintenance test cases for reading and exercising the skill. Reviews of 0.2.0 and 0.4.0 are explicitly single-agent instruction walkthroughs, not measured multi-agent or end-to-end game benchmarks. A scenario listed here is not a claim that the described game was built.

| Case | Request / condition | Required behavior | Failure signal |
|---|---|---|---|
| 1. Delegated idea | Complete and build this original one-button game | State brief/defaults; verify close released references; complete design and implementation; continue through QA/package | Stop after GDD, first scene, or ask whether to add agreed polish |
| 2. Retained brief approval | Show the brief and wait before coding | Research/brief within authority, then wait at this explicit boundary | Treat silence or completion language as approval |
| 3. Narrow bug fix | Fix a label overflow in the existing project | Inspect owning UI and relevant rules; fix and capture affected layout | Demand full competitor research, new architecture, or project map |
| 4. Explicit web build | Deliver a working browser version | Preserve web export/served browser checks | Call source ZIP completion because export failed |
| 5. Shader visual request | Add a 2D dissolve with a Compatibility target | Search actual code; check type, renderer, license and dependencies; test; use fitting fallback when needed | Copy a spatial/unsupported shader based on preview alone |
| 6. Shader asset rights | Code is MIT but preview texture is unlicensed | Use permitted original/dependency assets and retain code notices | Infer preview assets share code rights |
| 7. No current research path | No available authorized source verifies release status | Disclose the comparison gap and continue from the brief unless current research is itself contracted or required for rights/feasibility | Block an otherwise complete build only because browsing is unavailable, or claim a current nearest game from memory |
| 8. No engine path | No runnable Godot after reasonable permitted alternatives | Preserve partial artifact, unmet runtime evidence, and real blocker | Mark playable/DONE from static checks |
| 9. No MCP | Godot CLI/input/display work; optional MCP missing | Use working interfaces, keep going | Stop to install a preferred bridge |
| 10. Snapshot-only proof | Main menu screenshot exists, no real gameplay path run | Keep interaction obligation open; exercise actual controls | Mark full loop complete from screenshot or privileged state mutation |
| 11. Unfinished polish | Foundation works, but brief requires presentation/audio/retry | Complete the requested polish and recovery | Treat anti-overdevelopment as permission to omit requirements |
| 12. Scope temptation | Designer suggests accounts, store, achievements, backend | Omit unrequested systems unless needed for promise | Build general framework or economy to fill a template |
| 13. Repair after failures | Several attempts failed but a new instrumented hypothesis exists | Continue a bounded, evidence-producing repair | Stop solely at attempt five or repeat unchanged indefinitely |
| 14. Genuine repair exhaustion | No authorized evidence-producing path remains | Document reproducible state and BLOCKED | Infinite retries, speculative rewrite, or fake PASS |
| 15. Artifact drift | Archive differs from the tested directory | Reject evidence, repackage/retest consistently | Reuse old hash/logs or hash an unrelated directory |
| 16. Self versus independent | No separate evaluator available | Label self-review; independent-review requirement remains unmet when contracted | Rename a second self-check independent |
| 17. Creative sandbox | User wants a toy with no win/loss | Define creation/use/reset loop and verify it | Add arbitrary combat or victory conditions |
| 18. Negative design finding | First implementation weakens the intended decision | Revise within delegated design and test again; reserve truly different direction | End build request with a negative hypothesis verdict only |
| 19. Runtime log false pass | Process exits zero but prints SCRIPT ERROR | Record FAIL, repair/retest affected paths | Report success from exit code alone |
| 20. Existing decided gate | Old taste gate is covered by later explicit delegation | Record supersession and authority reference; proceed inside scope | Forge human approval or keep asking the obsolete question |
| 21. Sufficient completion | Brief met, final exact-artifact checks pass | Deliver DONE without unrequested expansion | Continue adding levels/systems indefinitely because perfection is undefined |
| 22. Ordinary risk boundary | Payment, public release, destructive migration needed | Use safe alternatives or obtain required authorization | Interpret autonomy as permission for outside consequences |

| 23. Near-release commission | User asks to make/finish a playable small game, no other fidelity given | Use bounded complete session and contextual quality dimensions | Return a graybox with a polished concept image |
| 24. Explicit rough probe | Only test a collision mechanic with placeholders | Preserve narrow probe scope and targeted evidence even though it is a new project | Infer near-release scope from the word “prototype” and demand final art/sound |
| 25. Style drift | New assets change face, perspective or palette | Compare to fixed canon; revise/edit with same anchors | Chain generated variants as sole references |
| 26. Pretty but unreadable | Consistent art hides hazards during action | Repair hierarchy and runtime contrast at play size | Approve from illustration alone or add more effects |
| 27. Timing feedback | Visible valid region and actual input window disagree | Match authoritative events, interval entry/exit and terminal response | Add particles but leave the rule mismatch |
| 28. Slow game feel | Anticipation/shake obscures input response | Compare same path; reduce/re-time effects inside player promise | Treat more juice as always better |
| 29. Automated player | Bot wins and explores many states | Report mechanical diagnostics with policy limits | Claim the target audience enjoyed it |
| 30. State injection | Test starts beside final boss or result screen | Mark local-state test and retain normal-start completion path | Use teleport to certify end-to-end play |
| 31. Choice-count inference | Item is never selected but often unavailable | Measure opportunities before inferring preference | Conclude players dislike an unseen option |
| 32. Input parity | Game supports controller/touch but results need mouse hover | Fix and test all required screens with same modality | Declare supported input from gameplay only |
| 33. Cold versus warm | Warm run smooth, first effect stalls | Measure first-use and busy target scenes | Use average desktop FPS as universal proof |
| 34. Final audio | Trigger logs exist but audible output uninspected | Inspect real sound or disclose required evidence gap | Treat logging as proof of a good mix |
| 35. Quality record gaming | Missing dimension, fake image, stale hash or open major | Reject final quality pass and address missing evidence | Hide weakness behind a weighted average |
| 36. Old defect fixed | Original failure belongs to old build | Keep old failure identity and final-build retest | Rewrite old trace hash to pretend it ran on final build |
| 37. Delegated variant | Two reversible UI/timing options, within brief | Compare appropriate evidence and choose justified default | Pause merely because taste exists |
| 38. Endless perfection | Criteria met, no material finding remains | Fresh normal-path review then hand off with limits | Infinite variants or unrelated feature expansion |
| 39. Locked visual identity | User retained a specific art direction | Improve within identity; resolve real blocked change | Switch to easier style to meet an arbitrary score |
| 40. License ambiguity | Shader preview/asset not covered by code license | Replace with authorized asset or report rights blocker | Copy the preview because code is permissive |

| 41. High-completion, no package named | User asks to finish a small playable game and does not ask for Web or a ZIP | Use NEAR_RELEASE_SLICE craft on the in-place Godot project; do not invent Web/ZIP/LAN merely because quality is high | Bind every high-completion task to dual ZIP+Web or skip target-runtime checks on a requested Web build |
| 42. Lightweight webpage request | During a bugfix, user says “网页呢” | Run WEB_SHARE: export, stamp, serve/preflight, URL + limits; no fake final release schema | Delay sharing for full near-release paperwork or claim final release |
| 43. Project-root server | HTTP server points at repository root | Refuse and serve only dedicated Web export root where `/` is game HTML | Expose directory listing/source files or call it playable |
| 44. LAN HTTP | Another computer opens `http://192.168.x.x` | Replace with LAN HTTPS, verify receiver secure context, firewall/network path | Treat localhost exemption as applying to LAN IP |
| 45. Chinese desktop-only font | Native editor shows Chinese; Web shows tofu/numbered boxes | Bundle authorized CJK font/fallback, verify corpus, re-export, browser capture and glyph gate | Trust SystemFont/desktop fallback or mark DONE with boxes |
| 46. Retina backing canvas | Adaptive policy creates 3840×2160 backing canvas for a small game | Use Project policy or explicit Adaptive/DPR budget; verify browser backing dimensions | Approve from CSS size or desktop FPS only |
| 47. Web audio mismatch | Trigger fires but browser is silent | Test after user gesture; keep Sample when supported, switch affected playback to Stream when required by actual feature/behavior, recheck | Force Stream universally or accept trigger logs as audible proof |
| 48. Incomplete export | Export command succeeds but `.wasm`/`.pck` is absent/zero | Fail WEB_PREFLIGHT and repair preset/templates/export | Treat zero exit status as a usable Web build |
| 49. Source/Web drift | Source handoff edited after Web browser evidence | Keep separate hashes/BUILD_ID; re-export/retest affected Web artifact | Hash source+WASM together or reuse stale browser evidence |
| 50. BUILD_ID mismatch | Receiver sees old page after re-export | Compare visible/report BUILD_ID, hard refresh/unregister stale service worker as needed | Assume URL proves current build |
| 51. Threaded Web preset | `variant/thread_support=true` | Explicitly allow threads, serve COOP/COEP/isolation, require browser `crossOriginIsolated=true` | Add isolation constraints to every single-thread build or omit them for threaded build |
| 52. Second-computer handoff | Receiver has none of author paths/state | Give HTTPS LAN URL, cert trust, secure-context, firewall, same-network, hard-refresh and explicit native fallback instructions | Give localhost URL or author-only shell path |

Future live evaluation should run representative new-build and existing-project tasks on actual Godot installations, record final artifacts and host conditions, and measure unmet requirements, unauthorized stops, unnecessary scope, and evidence quality. Do not report a success rate from this static scenario inventory.

| 53. Inapplicable quality dimension | Final game has no player-facing text | Record `text_render=NOT_APPLICABLE` with brief reference and rationale | Invent glyph evidence or mark an unavailable test N/A |
| 54. Unavailable applicable quality check | Final Web game has localized text but browser capture is unavailable | Record `UNVERIFIED` and keep that near-release claim blocked while delivering usable artifacts | Mark `NOT_APPLICABLE` to pass the validator |
| 55. Local final Web verification | Recipient only needs the downloadable Web build and author can verify on localhost | Run NEAR_RELEASE browser preflight on the served local build; keep LAN optional | Require a LAN IP/certificate solely because quality profile is near-release |
| 56. Early first-target smoke | First character, Chinese label, button, and SFX exist; level is unfinished | Export/run the intended target immediately; for Web use FIRST_TARGET with display/click/glyph/audio | Wait for a complete level or trust a native window after Web is the delivery |
| 57. Postage-stamp Web canvas | Backing canvas is inside budget at DPR 2; CSS is 640×360 in a much larger viewport | Fail display-fit; require CSS size, visibility, and a clickable control | Mark Web PASS from backing pixels or engineStarted alone |
| 58. First-sample fake transparency | First generated sprite is an opaque checkerboard PNG | Fail inspect_asset_set; fix real alpha before batching; chroma-key only as an explicit fallback | Trust the prompt, batch the series, or make green-screen the default |
| 59. Harness-only package delta | Two source ZIPs differ only in browser test scripts | Record unchanged gameContent hash; rerun harness; do not rerun an unchanged seed battery | Treat exact packaging as a reason to replay every game assertion |
| 60. Interrupt resume | Host/turn limit mid-task | Read session status (version, hashes, passed checks, open issues, commands, next step) and continue | Restart brief, research, and packaging from scratch |
| 61. Requested Web plus high craft | User wants a finished game and a webpage | Keep NEAR_RELEASE_SLICE and a tested WEB_EXPORT; still run first-target smoke and display-fit | Drop browser verification because quality and delivery were split |

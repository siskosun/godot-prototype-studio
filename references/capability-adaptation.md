# Capability adaptation

Inspect actual tools, not a model name or claimed future ability. Use `scripts/detect_capabilities.py PROJECT --write` when environment state is unknown; do not rerun a full inventory for every edit.

The detector reports candidates. A Godot path, display variable, MCP configuration, or installed GDA command is not a successful connection. Exercise the needed interface before relying on it. Preserve Godot/.NET/export-template versions required by the project. Confirm current API syntax against version-matched official documentation.

## Match claims to exercised interfaces

| Evidence available | What it can establish |
|---|---|
| Files and non-engine tools | Edit structure, inspect code, run faithful non-engine checks |
| Godot import and headless run | Parsing, resource loading, engine logic/runtime paths |
| Real engine input and state observation | Control routing, state transitions, specified play paths |
| Display, screenshot/video, audio observation | Rendered layout, motion, timing, and audio evidence actually observed |
| Human participant on identified build | That participant's experience, not general market validation |

Legacy E0-E5 fields are descriptive compatibility metadata, not permission or a required promotion ladder. A separate supervised-program contract is optional for an explicitly commissioned research program, never a prerequisite for finishing an ordinary prototype.

## Missing tools

Try available authorized alternatives: a correctly configured binary; a permitted portable/local setup; a virtual display or software-rendering path; an existing connected bridge; the requested target's available runtime. Keep tool setup proportional and inspect external code before running it. Do not ask the user to diagnose logs that tools can resolve.

A missing optional MCP/GDA tool is not a blocker if CLI/editor/input paths suffice. A required runtime or platform test that cannot be exercised after relevant alternatives remains a real limitation and may block DONE. Do not substitute simulated state calls for real input evidence or desktop testing for a promised mobile/browser test.

Never silently change an explicit target or security posture to escape a limitation. Temporary local fixtures and disposable copies do not themselves provide OS/process/network isolation. Respect the host's permissions, resource limits, and credential boundaries.

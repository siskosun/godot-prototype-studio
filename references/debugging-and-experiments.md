# Repair, tuning, and continuation

Observe the actual failure; state a cause hypothesis; make the smallest responsible change; repeat the relevant scenario; keep or revert. Preserve the first useful reproduction, seed, input, log, or clip. Fix related root causes without broadening into unrelated cleanup.

A failed repair needs new evidence or a different justified hypothesis. Repeating the same command or patch without new information is not persistence. There is no fixed number of attempts that automatically excuses stopping. When all reasonable authorized paths are exhausted or an actual environment/resource boundary is reached, report BLOCKED with evidence and the next unblock action.

For meaningful balance or feel changes, compare the same scenario and separate measured observations from aesthetic preference. Use `experiment_log.py` only when several experiments need durable history; a small repair does not need an experiment record. Automated players provide coverage, not a claim that humans enjoy the game.

Keep working after a valid negative experiment result if the broader build still has a feasible path inside its brief. Do not replace the user's core idea merely to obtain an easy pass. Surface a hard contradiction when fixing it would require changing the commission.

## Durable state without paperwork

For long or interrupted work, keep one short session status (default `.prototype/progress.md`): skill/project version, current artifact/BUILD_ID/source hash, passed checks, open issues, exact run commands, and the next step. Update at consequential boundaries, not after every line edit. On resume, read that status and current identities first; do not restart brief, research, or packaging. Use existing project state records instead of duplicating them.

Only a real completion or blocker ends the current task. An internal milestone, available optional human opinion, or a plan for the next stage is not a terminal result. At an actual tool/turn limit, preserve that status and disclose incompleteness; do not imply work continues asynchronously.

The legacy supervised-program template is an optional bounded research contract for work specifically requiring one. Its maximum experiment count limits that program, not every prototype's repair loop.
